# 数据库与迁移

## 数据库配置

支持 PostgreSQL 与 SQLite。配置通过 `.env` 或 `app/config.py` 中的 DB_* 环境变量。

### WSL Docker PostgreSQL 示例

- 容器名：`postgres`
- 数据库名：`aiqore`
- 用户/密码：`postgres` / `postgres`
- 端口：5432

**使用 WSL IP 直连（无需端口映射）示例：**

在 WSL 中查看 IP：`wsl hostname -I`，在 `.env` 中设置：

```
DB_HOST=172.30.37.138
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=postgres
DB_NAME=aiqore
```

注意：WSL 重启后 IP 可能变化，若连不上需重新查 IP 并更新 `DB_HOST`。

**验证连接：**

```powershell
Test-NetConnection -ComputerName <DB_HOST> -Port 5432
```

```bash
uv run python -c "from app.database import engine; from sqlalchemy import text; c=engine.connect(); print(c.execute(text('SELECT version()')).fetchone()[0])"
```

### 使用 localhost（需端口映射）

若希望用 localhost，需映射端口后启动容器，例如：

```bash
wsl docker run -d --name postgres -e POSTGRES_DB=aiqore -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:latest
```

然后在 `.env` 中设置 `DB_HOST=localhost`。

## 初始化与迁移

### 应用迁移（建表与升级）

在 `backend/` 目录下执行：

```bash
uv run alembic upgrade head
```

或使用 VS Code 任务「UV: Alembic 升级数据库」。

### 创建新迁移

在 `backend/` 目录下执行：

```bash
uv run alembic revision --autogenerate -m "描述"
uv run alembic upgrade head
```

## 标的与相关表（当前 ORM）

- **instruments**：标的单表，`code` 为主键；含交易所代码、资产大类、标的类型、上市/到期日、简称、最新价、是否可交易等。详见 `app/models/instrument.py`。
- **sectors**：板块树与 `metadata`（JSON）、`remark` 等。详见 `app/models/sector.py`。
- **data_source_connections**：QMT/聚宽/tushare 等连接配置。详见 `app/models/data_source.py`（ORM 类名：`DataSource`，表名保持历史命名）。
- **strategies / backtest_tasks**：策略与回测任务。详见 `app/models/strategy.py`、`app/models/backtest_task.py`。
- **accounts / trades / positions**：账户与交易、持仓。详见 `app/models/account.py` 等。

数据库迁移已折叠为单文件 `alembic/versions/001_initial_schema.py`（revision `001_initial`），`upgrade` 通过 `Base.metadata.create_all` 与当前模型对齐。

## 已有数据库且曾使用旧迁移链时

若库中 `alembic_version` 仍为旧 revision（如 `015`），而表结构已与当前 ORM 一致，请勿再执行会重复建表的 `upgrade`；应改为：`uv run alembic stamp 001_initial`，将版本标记为新的 head。

## Windows 下 Alembic 编码问题

在 Windows 中文系统上执行 `alembic upgrade head` 或 `alembic revision` 时，可能出现：

```
UnicodeDecodeError: 'gbk' codec can't decode byte 0xa8 in position ...
```

原因：Windows 默认 locale 为 GBK，而 `alembic.ini` 为 UTF-8，Alembic 读配置时使用 locale 编码导致冲突。

### 解决方式

1. **推荐：使用 VS Code 任务**  
   运行「UV: Alembic 升级数据库」或「UV: Alembic 创建迁移」（`.vscode/tasks.json`）。任务已设置 `PYTHONUTF8=1` 与 `PYTHONIOENCODING=utf-8`，减轻 Windows 下读 `alembic.ini` 的编码问题。

2. **PowerShell 下先设 UTF-8 再执行**  
   ```powershell
   $env:PYTHONIOENCODING = "utf-8"
   uv run alembic upgrade head
   ```

3. **确保 `alembic.ini` 以 UTF-8 保存**  
   避免文件中出现非 ASCII 字符在 GBK 下被误读。

原因与 Alembic 读取 `alembic.ini` 时的系统默认编码有关；通过 `PYTHONIOENCODING` 或任务环境可避免 GBK 解码失败。
